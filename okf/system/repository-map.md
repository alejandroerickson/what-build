# Repository map

A pnpm workspace: two apps, two libraries and a package listing what the server leaves out of its bundle. The root holds only what a tool looks for there: the
workspace's own files (`package.json`, the lockfile, `pnpm-workspace.yaml`, `tsconfig.base.json`,
`vitest.config.ts`, `.nvmrc`), the ignore files git, Docker and `gcloud` read from the root,
`README.md`, `AGENTS.md` and `LICENSE`. Everything else is in a folder
([decision](../decisions/public-repository-reference-docs.md)).

| Path | What it is |
|---|---|
| `packages/core/src/` | The domain. `registry.ts` (operation definitions), `bounded-search.ts` (the limits a search runs within), `ops/*.ts` (the 118 operations by area; `ops/attachments.ts` getting attachments in, `ops/derived.ts` reading them and a source's derived text, `ops/search.ts` and `ops/plain-search.ts` search; `ops/deletes.ts` deletes a whole product or organization), `policy.ts` (roles and access), `deletion.ts` (what every permanent delete shares: its guards, tombstones and previews), `plans.ts` (what a plan and its limits are, the plans this process serves as the deployment defines them, and the guests' settings, importing nothing, so the web app and the public site share them as `@whatbuild/core/plans`), `settings.ts` (what an instance owner set of them, stored with the deployment and read over those defaults), `guests.ts` (letting a guest account in while there is room, and its place in line), `limits.ts` (their enforcement: the daily allowances, the totals an organization holds, the bytes sent to a person, and each refusal; `ops/limits.ts` reads them and moves an organization to another plan), `accounts.ts` (ending an account's sign-ins; `ops/accounts.ts` lists accounts for the instance's owners, and ends one, removed by an instance owner or deleted by its person), `account-deletion.ts` (what deleting an account does, in the words the deletion page, the privacy page and the confirmation mail share; the web app imports it as `@whatbuild/core/account-deletion`), `tenant-tables.ts` (the tables that hold an organization's content, in the order deletion needs), `evidence-move.ts` (moving retired insights and decisions into Evidence, run by the worker), `text-edits.ts` (exact edits and diffs), `field-aliases.ts` (accepted aliases for ids and fields), `html-rules.ts` (the HTML rules a Story page, a mockup page and an Idea card's front are each held to at write), `idea-card.ts` (an Idea card: the card kit agents draw fronts with, the document and headers a front is served with, the two-sides rule, and the kit's guidance for agents; its pictograms in `idea-card-icons.ts`, generated from lucide by `scripts/gen-card-icons.mjs`), `page-sandbox.ts` (the sandbox each is served and framed in; the web app imports it as `@whatbuild/core/page-sandbox`), `story-html.ts` (the Story's stylesheet rules and the headers every page is served with), `story-guidance.ts` (agent authoring guidance: style workflow, taste, design passes), `story-styles.ts` (the house style catalogue and its sample page; the styles one per file in `house-styles/`, with `kit.ts` for what they share), `story-fonts.ts` and `story-fonts/` (the typefaces the server embeds in a page that names them, with their licence, and the app's own Inter, which every Idea card's front carries), `story-theme.ts` (what the app's frame adds to a page), `prototype.ts` (a mockup's prototype: its paths, types, warnings, address and the headers every file is served with), `story-print.ts` (PDF print view), `text-index.ts` (the search index of what sources say, written with every text it covers), `plain-query.ts` (how plain search reads words, and its excerpts), `find-in-text.ts` (what a source's Find in the text marks, and counting it, which plain search's `match_count` and the web app's find share; the web app imports it as `@whatbuild/core/find-in-text`), `usage.ts` (counting every call and reporting it, naming nobody, and forgetting a deleted person's days), `safe-next.ts` (where a sign-in may return to; the web app imports it as `@whatbuild/core/safe-next`), `db.ts` (table types), `guide/` (the guide agents read through the `guide` tool: a Markdown file per topic, embedded as `guide-text.ts`). |
| `packages/parsers/src/` | Pure parsers from bytes to readable Markdown: text and Markdown, VTT/SRT cues, DOCX, legacy Word `.doc`, PDF, HTML, XLSX, CSV/TSV, XML; shared speaker-turn and table-row rules; `markdown.ts`, which lays every format's text out as one Markdown document; `numfmt.ts`, Excel's number formats, which a workbook's values read through; and `statuses.ts`, the statuses a file's name, type and size settle before it is read, and how a reading an earlier version made is said now. |
| `packages/server-external/` | A `package.json` and no code: the packages the server leaves out of its bundle (`apps/server/build.mjs` reads the list), which the image installs from `pnpm-lock.yaml` with `pnpm deploy` ([decision](../decisions/one-stateless-image.md)). |
| `apps/server/src/` | The Hono server. `app.ts` (composition), `rest.ts` and `mcp.ts` (the two front doors, generated from the registry), `auth/` (sign-in, sessions, tokens, OAuth server, and `page.ts`, the pages they render), `uploads.ts`, `prototype.ts` (the one route that serves a mockup's prototype), `canonical-host.ts` (moving a page opened on another name to the public URL), `null-characters.ts` (refusing a null character in any request before a route reads it), `site.ts` (the public site's host and interest form), `plans-config.ts` (reading the deployment's plans from `WHATBUILD_PLANS`, and refusing to start on one that is wrong), `plans-check.ts` (`pnpm plans`: checking a plans file before it is deployed), `worker.ts` (job queue: reading attachments, building the search index, exports, deleting blobs), `parse-process.ts`, `parse-child.ts` and `parse-worker.ts` (the child process each attachment is parsed in, and the worker thread in it, with their limits), `example-organization.ts` (naming the example organization at start-up), `migrations/*.sql`, `seed.ts` and `seed-content.ts` (the synthetic sample product), `dev.ts` (local development), `people.ts` (`pnpm people`: [synthetic people at scale](../operations/local-development.md#many-people) on a development instance), `fixture.ts` (pulling and loading a copy of production), `dataset.ts` (`pnpm dataset`: [the non-production dataset](../operations/the-non-production-dataset.md), a pull beside synthetic organizations), `organization-copy.ts` (what a [copy of an organization](../operations/copying-an-organization.md) takes and leaves), `usage-report.ts` (`pnpm usage`: [how a deployment is used](../operations/analytics.md), from every source it has), `e2e.ts`, `e2e-golden.ts`, `e2e-browser.ts` and `e2e-mcp.ts` (the instance and its golden master, the browser driver and the MCP client of the [end-to-end tests](../operations/end-to-end-tests.md)), `main.ts` (CLI: serve, worker, migrate, seed). |
| `apps/server/test/` | Server tests against an embedded Postgres. |
| `apps/web/src/` | The React app. `main.tsx` (routes), `routes/` (screens), `shell/` (panel, inspector, theme), `ui/` (primitives; `glyph.tsx` wraps the icons), `styles/` (`tokens.css`, `base.css`, `ui.css`, `shell.css`, `screens/*.css`), `lib/` (API client, session, formatting, Markdown), `system/` (a development-only specimen of every primitive at `/_system`), `site/` (the public site's pages, its front page and its plans; their HTML entries are `apps/web/site/index.html` and `apps/web/site/plans/index.html`). |
| `e2e/plans/` | The [end-to-end test plans](../operations/end-to-end-tests.md) an agent runs through the web app and MCP, and their format (`README.md`). |
| `scripts/` | `e2e.mjs` and `shots.mjs` (Playwright scripts against a running `pnpm dev`), `gen-guide.mjs` (embeds the guide's topics into core), `check-publishable.mjs` (nothing private is published), `security.mjs` (`pnpm security`), `tools.mjs` (the pinned scanners), `attention.mjs` (`pnpm attention`: what is waiting) ([security checks](../operations/security-checks.md)), `hostile-files.mjs` (hostile uploads for rehearsing a release, [dev deployment](../operations/dev-deployment.md#rehearsing-a-release)). |
| `scripts/githooks/` | The git hooks `pnpm install` turns on: `pre-commit`, `commit-msg` and `pre-push` run the publishable check. |
| `.github/` | Workflows (`ci.yml`, `pull-request-text.yml`, `security.yml`, `codeql.yml`, `release.yml`), `dependabot.yml`, the scanners' settings: `gitleaks.toml`, `osv-scanner.toml` (accepted vulnerabilities), `zap-rules.tsv`, and the issue forms in `ISSUE_TEMPLATE/` (a bug, a request, and links to the security policy and the contribution guide). |
| `deploy/cloud-run/` | `setup.sh` for the Cloud Run deployment, and `cloudbuild.yaml`, the build a release trigger or `gcloud builds submit` runs ([guide](../operations/cloud-run.md)). |
| `deploy/azure/` | `containerapp.yaml`, the container app's definition for a self-hosted deployment on Azure, which an agent sets up with the Azure CLI ([guide](../operations/azure.md)). |
| `deploy/cloudflare/` | `worker.js` and `wrangler.toml`: on Cloudflare's free plan, the public site from the edge and the app's domain from the Cloud Run service. |
| `deploy/Dockerfile` | The production image, built from the repository's root; it carries the example plans at `/app/plans.example.json`. |
| `deploy/plans.example.json` | The example plans, Free and Pro, in the form a deployment gives its own in `WHATBUILD_PLANS`; local development, the end-to-end instance and the tests offer them. |
| `okf/` | This bundle: all documentation. |
| `.agents/skills/` | Skills for agents working on this repository: `okf-orient`, `okf-update`, `okf-decision` ([decision](../decisions/agent-guidance-is-tool-neutral.md)), `azure-self-host`, the procedure for [hosting on Azure](../operations/azure.md), `make-a-release`, for [releasing](../operations/releasing.md), `rehearse-on-the-dev-deployment`, for [the dev deployment](../operations/dev-deployment.md), `perform-the-restore-drill`, for the restore drill in [backups](../operations/backups.md#the-restore-drill), `recover-a-deployment`, for [recovering from a bad release](../operations/recovering-from-a-bad-release.md), `test-on-a-copy-of-production`, for [a copy of production](../operations/a-copy-of-production.md), `copy-an-organization`, for [moving an organization into another deployment](../operations/copying-an-organization.md), and `audit-for-leaks` and `triage-security-findings`, for the [security checks](../operations/security-checks.md), `run-end-to-end-tests`, for the [end-to-end tests](../operations/end-to-end-tests.md), `read-usage`, for [how a deployment is used](../operations/analytics.md), and `set-up-mail`, for a deployment's [mail](../operations/mail.md), and `run-the-instance`, for an instance owner's work on plans, organizations and people. `.claude/skills` links here. |
| `apps/web/PRODUCT.md`, `apps/web/DESIGN.md`, `apps/web/.impeccable/design.json` | Product and design records, read by design tooling, which looks for them from the web app upward. |
| `.github/SECURITY.md` | How to report a vulnerability, which GitHub shows on the Security tab. |
| `.github/CONTRIBUTING.md` | How to run WhatBuild, make a change and open a pull request, short and pointing here; GitHub links it when someone opens an issue or a pull request. |
| `.claude/` | Two links for Claude Code: `skills` to `.agents/skills/`, and `CLAUDE.md` to `AGENTS.md`. Its local settings stay ignored. |
| `_private/` (ignored) | A checkout's private working material: notes, logs, scratch. Never committed. |
